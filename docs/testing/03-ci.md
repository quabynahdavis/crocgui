# 03 — Continuous Integration

The workflow is defined in `.github/workflows/ci.yml`.

## Triggers

```yaml
on:
  push:
    branches: [main]
  pull_request:
```

Every push to `main` and every pull request against any branch runs the full workflow. The two jobs
are independent and execute in parallel — a Rust compilation failure does not delay frontend
feedback.

## Frontend job

Runs on `ubuntu-latest`.

| Step | Command | Purpose |
| --- | --- | --- |
| Checkout | `actions/checkout@v4` | Fetch the repository |
| Setup Bun | `oven-sh/setup-bun@v2` with `bun-version-file: bun.lock` | Pin the Bun version to the lockfile |
| Install | `bun install` | Install dependencies |
| Type check | `bun run check` | `svelte-kit sync` then `svelte-check` |
| Test | `bun run test` | 60 Vitest tests |
| Build | `bun run build` | Verify the production frontend build succeeds |

Using `bun-version-file` rather than a hardcoded version keeps CI aligned with local development
automatically.

Note that `bun install` also fires the `postinstall` hook, which downloads the croc binary. CI does
not execute transfers, but a broken download script surfaces here as an install failure.

The build step matters even though tests pass beforehand: `svelte-check` and Vitest do not exercise
the full Vite production pipeline, so an adapter or import error can slip past both.

## Backend job

Runs on `ubuntu-latest`.

| Step | Command | Purpose |
| --- | --- | --- |
| Checkout | `actions/checkout@v4` | Fetch the repository |
| Setup Rust | `dtolnay/rust-toolchain@stable` with `rustfmt, clippy` | Install the stable toolchain |
| Cache | `Swatinem/rust-cache@v2` with `workspaces: src-tauri` | Cache the Cargo registry and build artifacts |
| System deps | `apt-get install ...` | Install the Tauri Linux libraries |
| Check | `cargo check` in `src-tauri` | Type check without linking a full binary |
| Test | `cargo test` in `src-tauri` | 55 Rust unit tests |

### System dependencies

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential curl wget file \
  libxdo-dev \
  libwebkit2gtk-4.1-dev \
  libappindicator3-dev \
  librsvg2-dev \
  patchelf
```

Even for `cargo check`, the `tauri` crate's build script needs the WebKitGTK development headers to
be present. `libappindicator3-dev` backs the tray icon and `libxdo-dev` backs window control — both
are compiled in because the tray code is gated on `#[cfg(desktop)]`, which is satisfied on Linux.

This is the same list documented in
[`../getting-started/01-installation.md`](../getting-started/01-installation.md); keeping the two in
sync means a green CI run implies a reproducible local environment.

### Caching

`Swatinem/rust-cache@v2` is scoped with `workspaces: src-tauri` because the Cargo project is not at
the repository root. It keys on the lockfile and toolchain, restoring the registry, git checkouts,
and `target/`. Without it, the Tauri dependency tree would be rebuilt from scratch on every run.

`rustfmt` and `clippy` are installed by the toolchain step but are not yet invoked by a workflow
step — they are available for a formatting or lint gate to be added without changing setup.

## What CI does not do

- **No bundling.** `cargo test` and `cargo check` run, but `tauri build` does not. Installer
  generation is a release-time concern and is described in
  [`../getting-started/03-building.md`](../getting-started/03-building.md).
- **No cross-platform matrix.** Both jobs run only on Linux. macOS and Windows behaviour — tray
  variants, `taskkill` cancellation, the `croc.exe` filename — is not exercised automatically.
- **No end-to-end tests.** Nothing launches the packaged application or performs a real transfer.
  The Vitest `exclude` list already reserves `e2e/*` for that possibility.
- **No formatting or lint gate.** `cargo fmt --check` and `cargo clippy` are not run.

## Reproducing CI locally

```bash
bun install
bun run check
bun run test
bun run build

cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
```

If these pass on Linux, CI will too. The most common cause of a local pass with a CI failure is a
dependency installed globally on your machine but absent from the runner — check that `bun.lock` is
committed and up to date.
